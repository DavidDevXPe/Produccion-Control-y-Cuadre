# Revisión de estabilización — 24 de octubre de 2026

## Alcance aplicado

Se aplicaron mejoras incrementales sobre el estado actual del frontend, sin
modificar los cálculos operativos, la conciliación, FIFO, Túnel, Tratamiento ni
los registros históricos.

- Se añadió `npm run test:coverage` con cobertura V8 y umbrales mínimos de 80 %
  en líneas, funciones y sentencias, y 70 % en ramas.
- El workflow de validación de pull requests ejecuta la cobertura además de
  TypeScript, ESLint, E2E y build.
- Se amplió el smoke E2E para cubrir la creación y búsqueda de un producto de
  catálogo, además de la navegación y captura de una jornada.
- Se agregó una verificación E2E para confirmar que activar Túnel sin
  movimientos reales no añade métricas al resumen Día/Noche.
- La información de jornadas, cierres, semana/proceso activo, catálogo y
  rendimiento se refresca cuando otra pestaña modifica sus claves de
  `localStorage`. Las escrituras de la pestaña actual mantienen el flujo
  existente.
- Se documentó esta revisión sin tocar los datos locales del navegador.
- Se conservaron las extracciones estructurales ya presentes en esta rama
  (`ProductionEntryContent`, `useProductionDataProviderValue`, componentes de
  paletizado y dropdown de Combobox). No se hizo una división masiva de los
  módulos de dominio puros porque requiere regresiones específicas por función.

## Puntos excluidos de forma deliberada

- El punto 7 (optimización de ExcelJS/PWA) queda pendiente por solicitud del
  usuario; no se cambiaron cargas ni estrategia de exportación.
- El backend y la migración de persistencia al servidor quedan para una fase
  posterior. Actualmente la aplicación sigue siendo local-first.

## Verificación local

La verificación actual registra 150 archivos y 852 pruebas aprobadas. La
cobertura V8 actual es de 82.98 % de sentencias, 74.85 % de ramas, 83.17 % de
funciones y 84.56 % de líneas. Los umbrales configurados quedan por debajo de
esta línea base para evitar una regresión silenciosa.

La auditoría actual de npm no reporta vulnerabilidades, ni incluyendo ni
excluyendo dependencias de desarrollo (`npm audit` y `npm audit --omit=dev`).
No se ejecutó `npm audit fix --force`.

## Próximos pasos

La modularización profunda de los módulos de dominio se mantiene como trabajo
posterior y deberá hacerse por extracción de funciones puras con regresiones
por módulo. La migración al backend deberá incluir autenticación, autorización,
esquema, migraciones, backups y una estrategia de transición de los datos
locales antes de activar escritura remota.
